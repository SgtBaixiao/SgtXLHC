# 站点工程化重构

本文给维护者和评审者说明本次重构的范围与验收条件。基线为 `d62e5b5`，目标是让现有静态站的数据更新、文章发布和图形交互可维护、可验证。

## 保留现有产品

保留 Astro 静态输出、GitHub Pages 项目路径、首页 Agent 图、进度图、随笔归档及现有视觉风格。Notion 凭据仍只从本地环境或被 Git 忽略的配置读取。此次交付是分支与 PR，部署仍由主分支发布流程负责。

## 数据更新要有明确契约

状态与进度数据共用可在 Node 和浏览器运行的验证模块。状态上报只投影公开字段，拒绝非法枚举、重复标识、无效时间和超限输入；损坏的旧数据不能被空对象覆盖。读改写使用跨进程锁与原子替换，并发上报不能丢失其他 Agent。陈旧心跳更新不能覆盖较新的记录。

进度解析保留数字依赖以及 Markdown 链接依赖，拒绝重复标识、缺失依赖和循环依赖，输出顺序确定。保留既有 schema 1.0 和默认 scratch 路径兼容性。浏览器遇到损坏或超限数据时继续尝试备用源。

## 发布模块负责完整流程

CLI 和本地网页共用发布模块，完整读取 Notion 数据库的分页。每篇文章必须属于配置的数据库且勾选 Published；发布日期、slug、源标识和目标路径都要验证。转换兼容 notion-to-md 的字符串和 parent 对象结果。

同一源文章重命名或改日期后继续更新原文件，并默认保留原 URL。其他文章或手写文章的文件与 URL 冲突必须拒绝，覆盖选项不能绕过源身份检查。准备整批内容后再写入，每个文件原子替换；失败可重试且不创建重复文件。并发发布串行执行。

提交与推送必须显式选择。Git 使用参数数组，提交范围只包含本次产物，拒绝已有暂存内容及目标文件的未提交改动。失败后保留本地文章并报告实际状态，不自动重试推送。

本地桥只绑定回环地址，校验 Host、Origin 和每次启动的请求令牌；限制请求大小、时间、页数和重复项。标题、标签和错误通过文本节点显示。覆盖与提交选项默认关闭，界面如实报告跳过、写入与推送结果。

## 图形组件可停止并释放资源

请求有超时和取消，停止轮询后不能回调或重新安排任务。网络失败会启动退避，并保留最后有效数据。

图形组件释放指针、键盘、缩放、观察器、动画和抽屉事件；空图可键盘操作而不抛错。邻接查询使用预建索引。减少动态效果时先得到稳定布局，隐藏或离开视口时停止计算。图形详情保留关闭按钮，并使用转义后的文本；同时提供键盘可达的节点列表。

## 验收依据

增加可复现的依赖安装、Node 行为测试、Astro 类型检查、根路径及项目路径构建、Playwright 浏览器测试和 PR CI。测试覆盖并发写入、损坏数据、Notion 分页与源身份、路径冲突、Git 提交范围、桥访问控制、轮询停止、抽屉与图形清理以及项目路径导航。加入大图固定样本检查，用于发现明显退化；不把样本结果表述为生产容量保证。

README 说明真实仓库、操作入口、兼容变化与失败恢复；设计文档记录模块边界和证据。完成后以固定提交分别检查代码规范与规格符合性，修复可复现问题。
